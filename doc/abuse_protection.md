# 追加契約なしの不正登録対策

## 適用範囲

Rack::Attackの既存Gemを利用。主催者・参加者・出展者を合わせ、同一IPからのPOSTをサーバーごとに制限する。

| 操作 | 各サーバーの上限 |
|---|---|
| 新規登録 | 1時間10回 |
| ログイン | 5分60回 |
| パスワード再発行 | 1時間10回 |

固定時間窓のため境界付近では上限の約2倍が可能。2台間は共有しないので、全体ではさらに2倍になり得る。共有回線の誤検知を避けた初期値であり、厳密な全体上限ではない。
IPはRails RemoteIpによって評価する。NginxがロードバランサーのX-Forwarded-Forを保持し、信頼するプロキシ以外のヘッダーを無条件に採用しないことが前提。

`tmp/abuse_counters` の64ファイルをflockで排他し、ワーカー間でカウントを共有する。キーはSHA-256、各ファイル最大2048キー、期限切れはアクセス時に破棄する。ディスク障害・容量上限では通過させて可用性を優先し、固定文言でエラーを記録する。ディレクトリはアプリ実行ユーザーのみアクセス可能にする。

登録の隠し入力欄に値がある場合は422。空欄または未送信は許可するため、人手や専用Botを完全に排除する機能ではない。IP変更・分散Botも残る。国外遮断、CAPTCHA、メール認証は今回未導入。

## 計測と運用

2秒以上のRails処理は `[Slow Request]` にcontroller/action、HTTP状態、処理/DB/view時間のみ記録する。現行productionのerrorログ設定でも出るようerrorレベルを使用するが、この行自体は例外発生を意味しない。URL・メール・パスワード・SQL・本文は出さない。ログの保存期限・ローテーションは既存サーバー設定に従う。

HTTP 429数、正常登録数、5xx、主要画面のp95、両サーバーCPU/バースト残量を比較する。429が正常ユーザーに多い場合は該当ルールだけ緩和する。前回の大量関連読み込みとワーカー数変更は再投入しない。

## 検証・展開

`bundle exec ruby test/security/abuse_protection_test.rb` は本番DBも認証情報も使わずに実行可能。実ミドルウェアで閾値、全登録経路、別IP、GET、XFF偽装、複数プロセス競合、期限切れ、ログ秘匿、honeypotを確認する。
本番でアカウント作成や大量POST試験は行わない。デプロイ後に主要公開画面と登録フォームのGETを確認する。
今回DBマイグレーション・追加Gem・外部登録は不要。取り消す場合は対策コミットをrevertして既存ワークフローで再デプロイする。
