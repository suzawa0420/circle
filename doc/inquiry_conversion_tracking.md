# お問い合わせ入口のクリック計測

## 計測の定義

- GA4イベント名: `circle_inquiry_click`
- 新規・既存、ログイン前・ログイン後を問わず、サークルへの問い合わせ入口リンクを押すたびに記録する。
- 対象: サークル詳細の問い合わせボタン、モバイル問い合わせボタン、メッセージアイコン、口コミページ、旧問い合わせページの入口。
- 警告対象サークルは警告を開いた最初のクリックを数える。警告内の「注意事項を確認して進む」は追加で数えない。
- フォーム送信や送信成功の件数ではない。連続してクリックすればクリックの回数分を数える。
- 追加データはイベント名だけ。氏名・メールアドレス・問い合わせ本文・金額を追加送信しない。通常のGA4ページ・セッション情報は既存Googleタグの設定に従う。
- 計測拒否・広告ブロッカー・通信失敗等がある場合、実際のクリック数より少なくなることがある。

## GTM / GA4設定

| 項目 | 設定 |
| --- | --- |
| GTMコンテナ | `GTM-MD88D9HB` |
| Googleタグの測定ID | `G-CEVJ1PHKXE` |
| GTMタグ | `GA4 - circle_inquiry_click` / GA4イベント |
| GTMトリガー | `CE - circle_inquiry_click` / カスタムイベント |
| トリガーのイベント名 | `circle_inquiry_click`（完全一致・正規表現なし） |
| GA4キーイベント | `circle_inquiry_click` |
| カウント方法 | イベントごとに1回 |
| デフォルトのキーイベント値 | 設定しない |

既存の `お問い合わせ_参加者` は `page_view` と `page_path` の `/thanks$` を条件とする旧完了ページ計測。今回のクリック数を見る場合は `circle_inquiry_click` を指定し、キーイベント合計と混同しない。

## 流入経路と割合の見方

GA4の「トラフィック獲得」で「セッションの参照元 / メディア」またはチャネルを選び、キーイベントを `circle_inquiry_click` に絞る。クリック数と「セッション キーイベント率」を確認する。

セッション キーイベント率は「そのクリックが1回以上あったセッション ÷ 全セッション」。クリック総数をセッション数で割った値とは異なる。初回流入を比較するときは「ユーザー獲得」の最初の参照元 / メディアを使用する。

設置前のクリックを新イベントとして遡って集計することはできない。公開後はリアルタイムやTag Assistantで受信を確認し、通常レポートへの処理を待つ。

## 検証と公開

`node test/security/circle_inquiry_tracking_js_test.js` で重複登録、警告との共存、対象外操作、送信項目を確認する。Railsの `test/integration/circle_contact_warning_test.rb` で通常と警告対象のリンク属性を確認する。両テストは本番デプロイ前のCIに含まれる。

GTMのプレビューで対象クリックからイベントタグが1回発火することを確認する。実際の問い合わせ送信は不要。GTMコンテナ公開とアプリのデプロイが揃って計測が有効になる。公開状態はGTMバージョンとGitHub Actionsで確認する。

問題時はGTMを直前の公開バージョンへ戻し、必要に応じてアプリ変更をrevertコミットで戻して通常デプロイする。DB変更はない。
