# 参加者チャットと相互評価（ローカル実装）

## 合意した動作

- 閲覧は無料・登録不要。新しい問い合わせは参加者登録・メール認証が必要。
- 同じ参加者と同じサークルの会話は1つ。主催者が最初に返信した時点で受付となり、双方に14日間の評価権が発生する。
- 評価は既存方式の「良かった／残念だった」。表示点は良かった割合×5。サークル側は従来の口コミと合算する。
- 双方の投稿完了か期限終了で公開する。一方だけでも期限終了時に公開。公開前は相手の投稿内容・点数を取得できない。
- 公開前は自分の評価の編集・削除・期限内の再投稿が可能。公開後は編集不可、本人削除は可能、再投稿不可。
- 公開後に削除した評価は表示・点数・件数から除外。再投稿防止のため権利消費の記録を残す。相手の評価・公開状態は変えない。
- 参加者からの口コミはサークル詳細・口コミ一覧に公開。主催者からの評価は参加者の公開プロフィールに掲載。問い合わせ一覧・チャットにも参加者の点数と件数を表示する。
- 実際の参加は自己申告。チェックした口コミだけ「参加した感想（自己申告）」と表示。
- 旧口コミも同じ一覧・集計に残す。既存の会員付き口コミがある参加者は同じサークルに追加投稿できない。旧匿名口コミの投稿者を新アカウントへ自動で紐づけることはしない。

## チャット・安全性

- ログイン中の参加者本人または対象サークルの現在の主催者のみ、閲覧・送信・自動更新が可能。URLのIDを変更しても別の会話を取得できない。
- 公開プロフィールに出すのはニックネーム、自己紹介、公開済み評価。住所・メールアドレス・会話本文は出さない。
- 相手のブロックで双方の送信と再問い合わせを停止。解除できるのはブロックした側のみ。両側がブロックした場合は双方の解除が必要。
- ブロック後も履歴・通報・発生済み評価権は残る。
- メッセージ単位・公開評価単位の通報を用意。相手には通報内容を表示しない。運営専用の `/super_admin/chat_reports` で対象と履歴を確認し、対応済みにできる。
- 未返信の報告は既存の `respond_check = "NG"` の判定・スコア計算をチャットにも適用。主催者の初回返信で解除する。
- 初期の送信上限は同一会話の同じ送信者につき10件/分、新しい問い合わせ先は20サークル/24時間。
- 自分の主催サークルへの問い合わせは、主催者ログイン状態または同一メールアドレスで検出して拒否。
- メール認証リンクはログインした本人のみ、24時間有効。GETでは認証せず確認ボタンで確定。メールアドレス変更後は再認証。
- 主催者もメール認証が必要。新規アカウント登録後は確認画面へ進み、確認完了までサークルの新規登録・チャット返信・評価投稿を制限する。既存主催者も返信・評価投稿の前に確認し、受信済みチャットの閲覧は可能。
- 参加者・主催者とも、新規登録完了時に確認メールを自動送信。確認画面から再送可能（送信後1分は再送を制限）。送信障害時も登録を維持し、画面に送信失敗と再送方法を表示する。
- 会話ページは `private, no-store`、検索除外、Turbolinksキャッシュ除外。送信内容・通報・認証トークンをパラメータログから除外。
- 確認メール画面と運営の通報画面には広告・GTMを載せない。

## 通知・広告

- メール本文に会話内容を入れず、ログイン必須のチャットリンクのみ通知。
- 最初の未読から5分待ってまとめる。同じ会話・同じ宛先には最低15分間隔。閲覧済み・ブロック中なら送らない。
- 表示中の会話は15秒間隔で更新。別タブ・非表示中は取得を停止する。広告やページ全体は更新しない。
- チャット一覧・詳細に既存の広告枠を1つ表示。会話や送信フォームから離した位置に設置。
- 通知予定と評価期限はDBに保存。`chat:maintenance` が通知送信と期限公開を処理する。ブラウザーを閉じても失われない。
- メール障害時は他の会話の処理を続け、失敗分を次回再試行する。送信直後のプロセス停止など、メール配信とDB確定の間の障害では重複通知の可能性が残る。

## 移行

- 旧問い合わせの新規画面・POSTは新しいチャット入口へ誘導。公式LINEへの問い合わせボタンと主催者のLINE問い合わせ設定欄を撤去。
- 過去のメール問い合わせ履歴と既存の連絡・報告経路は維持。チャットへ自動移行しない。
- 既存会員も、新規チャット送信前にメール確認が必要。従来のログイン自体は引き続き可能。
- 新機能を利用するにはマイグレーションと定期処理が必要。本番への適用は別作業。

## 今回のローカル環境

本番からコピーしたデータは使用していない。PostgreSQLはローカルの127.0.0.1:55439、データ領域は `/private/tmp/circle-chat-pg`。開発DB `circle_chat_development`、テストDB `circle_chat_test` を使用する。

```sh
# PostgreSQLが停止している場合
pg_ctl -D /private/tmp/circle-chat-pg -l /private/tmp/circle-chat-pg-server.log -o '-p 55439 -h 127.0.0.1 -k /private/tmp' start

# 開発サーバー（別ターミナル）
DATABASE_URL=postgresql://suzawa@127.0.0.1:55439/circle_chat_development CHAT_LOCAL_PORT=3100 RAILS_ENV=development bundle exec rails server -b 127.0.0.1 -p 3100 -P tmp/pids/chat-preview.pid

# 通知・期限公開（別ターミナル）
DATABASE_URL=postgresql://suzawa@127.0.0.1:55439/circle_chat_development CHAT_LOCAL_PORT=3100 RAILS_ENV=development bundle exec ruby bin/chat-maintenance
```

- 入口：`http://127.0.0.1:3100/conversations`
- 参加者ログイン：`/members/sign_in`、アカウント `chat-member@example.test`
- 新しい問い合わせ・評価を試す参加者：`chat-new-member@example.test`（同じデモパスワード）。既存のデモ会話は相互評価の公開まで操作済み。
- 主催者ログイン：`/admin_users/sign_in`、アカウント `chat-owner@example.test`
- 上記はこの隔離DB専用の架空デモアカウント。共通デモパスワードは `Local-demo-2026`。
- 2つのブラウザープロフィールでそれぞれログインすると往復を確認しやすい。
- メールは実送信せずLetter Openerに保存。`http://127.0.0.1:3100/letter_opener` で確認可能。
- 架空データの作成元：`db/seeds/chat_demo.rb`。指定のローカルDB以外では実行不可。
- 通報管理は専用のウェブマスター認証のみ。デモ主催者に運営権限は付与していない。専用ログインについては `doc/webmaster-admin.md` を参照。
