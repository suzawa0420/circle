# アフィリエイト広告カードの運用

## 変更する場所

案件・コピー・画像・リンク・対象ジャンル・掲載面は `config/affiliate_ads.yml`、
表示は `app/views/layouts/ads/_affiliate.html.erb`、見た目は
`app/assets/stylesheets/_affiliate_ads.scss` に集約する。
新しい案件のためにHTMLや案件専用CSSをコピーしない。現在のLanCulも同じ共通部品を使う。
設定の変更はレビュー・テスト・通常デプロイで反映する。運営画面やDBへの直接入力は不要。

## 案件の追加・停止

1. ASPでサークルブックを掲載サイトとして提携し、承認を確認する。
2. 設定に案件を追加する。準備中は `enabled: false` と `approved: false` にする。
3. ASPが発行した画像URL・画像用リンク・テキスト用リンク・対応する計測ピクセルを設定する。
   IDやURLを推測・生成しない。公式バナーは切り抜き・文字消し・再加工をしない。
4. `events` はEventの公開slug、`placements` は下記の掲載面から必要なものだけ指定する。
   全ジャンルへの一律掲載はしない。恋活広告をスポーツ仲間探し全体へ自動拡張しない。
5. 承認済み案件だけ `approved: true`、公開する段階で `enabled: true` にする。
   同じジャンル・掲載面に複数案件が該当する場合は、設定ファイルで先にある案件を1件表示する。
6. 公開画面を確認し、ASPへ代表掲載URLを提出する。ログインが必要な個人のURLは提出しない。
7. 募集終了・提携解除・条件不一致時は `enabled: false` にして通常デプロイする。

URLはHTTPS、コピーはプレーンテキスト。設定に認証情報・APIキー・利用者情報を保存しない。
価格や期間限定キャンペーンは、更新が必要になるため通常のカード文面には載せない。

## 掲載位置

- `search`：該当ジャンルのサークル2件の次、3枠目。1件しかなければその後。
- `search_empty`：該当ジャンルが選択された0件検索。キーワードだけでジャンルを推測しない。
- `blog_search` / `blog_search_empty`：該当ジャンルのブログ一覧。2件の次、または0件時。
- `circle_blog` / `circle_blogs`：該当ジャンルのサークルブログ本文下・サークル別ブログ一覧。
- `participant_mypage`：興味に該当ジャンルを登録した参加者だけ、おすすめサークルの下。

公開プロフィール・メッセージ画面には出さない。検索結果の広告は1枠とし、
同じ一覧の途中に全幅AdSense行を追加しない。既存の一覧末尾の広告は別枠として扱う。
別ジャンルの既存広告は変更しない。

## デザイン規定

- サークルと同じ全周の境界線・角丸・白背景を使い、冒頭に必ず「広告」とサービス名を表示する。
- 本文内余白16px、画像領域は最大幅180px・高さ150px。`object-fit: contain` で画像全体を保つ。
- 見出しは36文字以内・17px、説明は70文字以内・13px、リンクラベルは24文字以内。
  強制改行や長い文章でカードを縦に伸ばさない。カード冒頭の「広告」は省略しない。報酬の仕組みの長文はカード内で繰り返さず、
  フッターから常時たどれる `/advertising` にまとめる。
- CTAは最低44px。キーボードのフォーカスを見える状態にし、画像に代替テキストを付ける。
- PCは2列の通常の1枠、SPは1列の3枠目。順番をCSSで入れ替えない。
- PCの一覧は `align-items: start`。広告やサークルを行の高さまで引き伸ばさない。
  `height: 100%`、余白での高さ合わせ、固定のカード高、文字の切り捨てで揃えない。
- 本番の実例で広告がおおむね400px前後に収まり、隣のサークル下部に不自然な空白が
  生じないことを確認する。掲載面や画面幅で自然な高さが変わることは許容する。
- 外部広告リンクには `sponsored nofollow noopener` と別タブを設定する。
  ASPが発行した画像・テキストそれぞれのリンクと計測ピクセルを対応させる。

## 検証・キャッシュ・反映

`bundle exec rails test test/integration/lancul_ads_test.rb test/helpers/affiliate_ads_helper_test.rb`
で、対象ジャンル、0件検索、ブログ、興味の変更、3枠目、別ジャンルへの非表示を確認する。
PC・SPの実画面で画像と文字、隣の自然な高さを確認し、広告リンクをテスト目的でクリックしない。
一覧キャッシュには設定内容のダイジェストを含めるため、コピーやリンクを変えると更新される。
HTML構造の変更時は、一覧部分のキャッシュバージョンも更新する。
共通CSSが `public_listing.css` に残っていることもテストする。

masterへのpushは本番反映を開始するため、その作業の許可がある場合だけ実施する。
通常のテスト・アセット生成・server4/server5の順次反映を使う。
今回のカード変更には新規マイグレーションは不要。問題時は当該変更のrevertを通常デプロイする。

## 広告表示の方針（2026年10月21日確認）

カードは冒頭の「広告」で明示し、記事は冒頭の広告表記を維持する。
まとめページへのリンクだけで広告であることの表示を代替しない。
「報酬が入る場合があります」という特定の長文は共通カードに必須とせず、
報酬の仕組み・利用プログラムは広告説明ページへ集約する。
Amazonの参加者表示は同ページに維持し、GoogleのCookie説明と設定方法は
プライバシーポリシーにも記載する。広告主から個別の表記指定がある場合は優先して確認する。
