# 欠席申告の対応

欠席申告は主催者が記録し、本人は会話画面から説明・異議申し立てを送る。
運営の承認は不要。本人の説明は従来どおり会話・プロフィールの申告導線で確認する。
新しいメール通知や自動確定処理は追加しない。

主催者は自分の会話内の申告を取り下げ、集計対象外にできる。
本人や別の主催者は取り下げられない。申告の削除、本人の説明の変更、
集計対象への復帰は行わない。日時ごとの重複防止も維持する。

管理画面は最新順で報告と本人の説明を閲覧するための記録画面とする。
確認状況の更新ルート・フォーム、欠席申告の確認待ちバッジは廃止する。
過去の運営メモは管理者だけが閲覧できる。

既存のDB値は維持する。pendingは「主催者からの申告」、confirmedは
「運営確認済み（旧記録）」、dismissedは「集計対象外」と表示する。
pendingとconfirmedは従来どおり集計し、dismissedは除外する。
無回答・時間経過による確定や既存報告の一括更新は行わない。

マイグレーション不要。masterへのpushで既存のCI、アセット準備、
server4/server5のPuma順次ホットリスタートとヘルスチェックを実施する。
問題時は変更をrevertしたコミットを通常デプロイする。
取り下げ済みのデータは保持し、DBロールバックは行わない。
