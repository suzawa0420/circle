# 参加者の新規お問い合わせ上限

参加者アカウントごとに、日本時間の1日（00:00以上、翌00:00未満）に初めて
問い合わせるサークルを5件までに制限する。すでに問い合わせたサークルへの返信、
主催者返信、主催者同士の練習試合相談にはこの上限を適用しない。
既存の短時間連投・スパム・本人確認・ブロック制御は維持する。

## 判定と競合

- 会話の作成日時ではなく、サークルごとの最初の参加者メッセージ作成日時で数える。
- 空の会話、自動案内だけの会話、失敗した送信では枠を消費しない。
- 保留・スパム判定・ソフト削除済みも数える。審査後の配信日時では数え直さない。
- `Conversation#send_message!` の参加者行ロック内でチェックするため、新規送信と
  既存会話経由の送信の両方を守り、複数アプリサーバーへの同時送信も直列化する。
- データ移行は不要。公開当日も既存の初回送信履歴を数える。

## 表示

参加者のメッセージ一覧・会話画面・新規お問い合わせに残り件数を表示する。
上限時は新規フォームの送信を無効にし、サーバー側でも再判定する。
表示はページ取得時の値で、日付が変わったら更新する案内を表示する。

## 検証

`test/integration/member_inquiry_limit_test.rb` と
`test/integration/conversation_concurrency_test.rb` で、5件目/6件目、直接POST、
空会話、既存の返信、他アカウント、審査/削除、送信失敗、JST境界、残り1枠への
同時送信、主催者の非対象を検証する。既存会話・ブロック・審査・問い合わせ元・
練習試合の回帰テストも実行する。

## デプロイと復旧

DBスキーマ変更・データ移行なし。既存masterデプロイでCSS生成と2台のPumaの
順次ホット再起動を行う。問題時は本変更を通常のrevertコミットで戻し、同じ
デプロイ手順を使う。既存メッセージや利用者データは変更・削除しない。
