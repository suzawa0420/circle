# メッセージのリアクション

既存チャットの各配信済みメッセージ下にある顔アイコンから選ぶ。独立したスタンプメッセージは作成しない。

| アイコン | 短文 | 保存キー |
| --- | --- | --- |
| 👍 | 了解です | understood |
| 🙏 | ありがとうございます | thanks |
| ✅ | 確認しました | checked |
| ❤️ | いいですね | like |
| 😊 | 楽しみです | excited |

1メッセージにつき実際のアカウントごとに1件。同じ選択を押すと取消、別の選択で変更する。
`PUT /conversations/:id/messages/:message_id/reaction` は希望する状態（取消は空文字）を保存するため、通信再送で反転しない。
DBは参加者・主催者それぞれの部分一意インデックス、投稿者を1人に限定するCHECK、固定キーのCHECK、外部キーを持つ。
通常の会話と主催者同士の練習試合で既存の役割・アクセス判定を再利用する。アカウントIDをリクエストから受け取らない。
会話とメッセージを既存の編集・削除・審査と同じ順序でロックする。

自動案内、削除済み・未配信メッセージ、ブロック中・利用停止中にはリアクションを表示・操作できない。
変更時にChatMessageやConversationを更新せず、メール送信・通知予定・未読数・受付済み・評価権を変更しない。
リアクションは参加や予約の確定、初回返信の代用にはならない。

選択はキーボードでも操作でき、Escape・外側クリック・閉じるボタンで閉じる。CloseWatcher対応端末の戻る要求でも閉じる。ブラウザ履歴を書き換えないため、選択UIを閉じてもTurbolinksの画面復元を起こさず返信下書きを保持する。CloseWatcher非対応環境では閉じるボタン等を利用し、ブラウザの戻るは通常のページ移動となる。
連打時は同一メッセージへの保存を直列化し、失敗時は短いエラーと再操作可能な状態を示す。
既存の15秒ポーリングはリアクションの変化も検知する。選択中・保存中は履歴HTMLの差し替えを待つ。

検証はローカル専用データのみ。`test/integration/chat_message_reactions_test.rb`、既存の`conversation_concurrency_test.rb`とチャット関連統合試験、`test/security/chat_reactions_js_test.js`で権限・CSRF・再送・並行操作・メールなしを確認する。
PC/SP画面は外部通信を遮断して架空データで確認する。本番の実会話で試験リアクションを送らない。

## デプロイと戻し方

追加migration `20261030000000` は新規テーブルだけを作成し、既存メッセージを書き換えない。5秒のロックタイムアウトを使う。
両サーバーのprepareで冪等に適用し、全prepare完了後にPumaを順次ホット再起動する。適用失敗時はactivateへ進まない。
問題時はアプリケーション変更をrevertして通常デプロイし、追加テーブルと記録済みリアクションは保持する。
本番でのmigration downやリアクション一括削除はこのリリースに含めない。

## 操作行の表示

顔アイコン・選択済みリアクション・通報を折り返さない同じ行に配置する。顔アイコンと通報は44pxのタップ範囲を維持する。
狭い幅で長文リアクションが2人分ある場合は、選択済みリアクション領域だけを横スクロールさせ、全文と自分／相手の表示を保持する。画面全体には横スクロールを作らない。
選択・通報の内容は操作行の下に重ねて開き、行の高さを増やさない。両方を同時に開かず、外側クリック・Escapeで閉じる。通報文の下書きは閉じても保持する。
保存中の通知は読み上げ領域に残し、失敗時の案内は行の上に表示する。保存処理・権限・メール・未読への影響は変更しない。新規migrationは不要。
