# 詳細検索の見出しとSEO公開方針

## 対応した見出し

詳細検索では都道府県・市区町村・種目・募集内容・年齢層・タグ・自由入力キーワードを、実際に適用した条件から表示する。募集内容内・年齢層内の複数選択は「・」、両者の区切りは「／」。件数は実際の検索結果から取得する。ページ内の見出しは隅括弧なし、HTML titleは従来どおり隅括弧あり。

例：全12件 神奈川県の初心者／60代以上向けのバスケサークル募集

## 固定URLをサーバーで生成する方式

静的HTMLファイルを全パターン書き出す必要はない。同じRailsテンプレートで固定URLごとのHTMLを返せるため、検索エンジンからも通常のページとして取得できる。サークルの公開・募集状況変更を反映できることを優先する。

既存の種目・都道府県・タグ別ページを維持し、内容の等しいページを追加しない。詳細検索の募集内容はUsersGroup、年齢層はUsersAgeで判定している。既存タグ一覧のUserTagとは一致する保証がないため、名前が同じという理由だけで既存タグページへ転送しない。

## 初期公開範囲

- 地域・種目に、募集内容1つ・年齢層1つを加える組み合わせ。条件なしの次元も許容する。
- 公開サークルが存在する組み合わせだけを対象候補にする。結果の重複・検索需要・維持費用を確認して公開を絞る。
- 自由入力キーワード・複数チェック・並び替えは追加のインデックス対象にしない。利用者の検索機能としては維持する。
- 既存一覧に該当する組み合わせは既存URLへ統一する。条件の順序や重複指定が違っても同じ正規URLにする。
- 固定URLごとの見出し・HTML title・説明文・canonicalを揃え、詳細検索から対象ページへ案内し、サイトマップを用意する。
- 未知の条件・無効な組み合わせを適切に扱う。0件ページは新規インデックス対象にせず、公開済みページが0件になった場合の扱いも決める。
- サイトマップ生成は全組み合わせを個別に検索せず、公開サークルの登録条件から実在する組み合わせを集計する。
- 検索エンジンへの掲載は保証できない。公開後にSearch Consoleでクロール・インデックス状況と成果を確認する。

## 現時点の状態

固定URL・選択条件の見出し・サイトマップを実装する。URL形式は `/circles/find/{種目ruby}/{都道府県kana}/{募集内容ID}/{年齢層ID}`。指定しない次元は `all`。

単一選択で自由入力・市区町村・カテゴリー・タグの追加条件がない詳細検索は303で固定URLへ案内する。募集内容と年代の両方が未指定なら既存の一覧URLへ統一する。固定URLの条件をクエリ文字列で変更しようとした場合は301でパスの条件へ戻す。並び順はcanonicalから除外し、2ページ目以降のページ番号は残す。

0件の固定URLはHTTP 200で条件変更可能なフォームを表示し、noindex（nofollowなし）を付ける。空の2ページ目以降・未知の条件は404。複数選択・キーワード検索はnoindex。

検索条件の選択は上部の「詳しく絞り込む」に集約する。重複する下部の「条件からサークルを探す」は表示しない。固定URLへの検索時の案内とサイトマップ登録は維持する。

サイトマップは公開サークルのメイン・サブ都道府県と登録済みの募集内容・年代をSQLのGROUP BY CUBEで集計し、実在する組み合わせだけを追加する。無効なレコード・種目や都道府県の識別子が欠けた候補は除外する。公開状態や登録内容が変わった場合は次回のサイトマップ生成で反映される。生成・アップロード成功後には生成側サーバーの公開XMLキャッシュだけを解除し、アプリの他のキャッシュは維持する。別サーバーやHTTPキャッシュも新しい内容を取得できるよう、有効期間は5分にする。
