# メッセージの宣伝スパム確認

## 指定NGワード（2026-10-21）

「日本椿兔」を含むメッセージは、参加者・主催者の双方で新規送信・本文編集を入力エラーとして拒否する。初回返信の前後や通常会話・練習試合の区別によらず適用し、配信保留の点数判定とは別に処理する。空白・記号・不可視文字・HTMLや文字参照による分割も正規化して検出する。

参加者と主催者の名前・自己紹介、サークル公開プロフィール、自動返信テンプレートにも適用する。既存の本文は削除・再判定しない。既存メッセージの削除や運営判断、既存アカウントの無関係な項目の更新は妨げない。画像の中の文字は検査対象外。DB移行は追加しない。

## 通常のスパム判定

参加者からのメッセージを、主催者が初めて返信するまで判定する。主催者の返信後は通常の会話として本文判定を行わない。既存のメール認証、送信上限、ブロックは引き続き適用される。画像の中の文字は判定しない。

## 判定

5点以上を配信保留とする。成人向けサービスの宣伝表現4点、予約・料金等の勧誘表現2点、複数の外部リンク・連絡先2点、6個以上のハッシュタグ1点、運営が確認済みの誘導先5点。

取材・インタビューの依頼、記事・サイトへの紹介・掲載の申し出、自社商品・サービスの紹介は5点で配信保留とする。依頼・提案の表現との組み合わせで判定し、職業、属性、話題としての「取材」「営業」、URL単独では保留しない。外部リンクがない勧誘も対象。文面のルールに合わない言い換えは検知できないため、すべての営業連絡を保証して遮断するものではない。

集客支援・ホームページ制作・SEO対策・広告運用と「ご提案」「導入しませんか」等の組み合わせは5点。副業・副収入・不労所得・資産運用・投資案件・ネットワークビジネス等と「説明会」「ご招待」「稼げる」「収入を増や」等の組み合わせも5点。職業や興味としての単語だけでは加点しない。

LINE・オープンチャット・Telegram等への追加・登録と「詳しくはこちら」「詳細をご案内」等の組み合わせは3点。単独では保留せず、複数リンク・連絡先2点や送信行動と組み合わせる。通常のLINE交換・参加日確認だけでは加点しない。

同じ参加者による30分以内の初回返信前の投稿を最大60件比較する。別の2サークル以上へ50文字以上の同一・類似文があれば4点、別の7サークル以上への問い合わせは1点。比較では全角・半角、大文字・小文字、空白、句読点の差を除き、3文字ずつの組の一致率90%以上を類似文とする。短い挨拶、外国語、LINEという単語だけでは保留しない。

類似文の比較時だけ、先頭の短い「○○様／さま／さん」の宛名行を除外する。別の2サークル以上へ同じURLの誘導先（ドメイン＋パス）を送っていれば2点。同じサークル内の連投は複数サークルとして数えず、別参加者の送信や30分より前の投稿は合算しない。URL単独の反復は2点であり、通常のリンク共有をそれだけで保留にはしない。練習試合の問い合わせは同じ主催者アカウントが管理する送信元サークルをまとめて判定する。

## 運用

マスター管理画面の「スパム確認」に理由・点数・本文を表示する。保留・スパム確認済みの投稿は送信者と運営だけが閲覧でき、相手の一覧、未読数、通知、画像取得から除外する。運営の閲覧は既読にしない。

「配信を許可」で新着として配信し、通常の通知予定を作る。配信時刻順で表示し、古い投稿の許可でも閲覧済み扱いにしない。「スパムと確認」で配信せず、投稿内のURLのドメインとパスを次回判定に使用する。Telegram等のサービス全体は遮断しない。判断済み投稿は再処理しない。自動削除・自動アカウント停止は行わない。

参加者を利用停止にすると、配信済みの通常メッセージがある各会話へ「運営により、この参加者の利用を停止しました。」というシステムメッセージを記録する。主催者・参加者・運営の会話履歴では「運営からのお知らせ」と表示し、停止理由は公開しない。この案内はメール通知の予約・未読件数への加算を行わず、通常メッセージの既存の通知予定には触れない。配信保留だけの問い合わせや空の会話は対象外。停止中の理由追記・再操作では重複させず、解除後に再停止した場合は新しい履歴を追加する。既に停止済みの参加者への遡及追加は行わない。

現在利用停止中で、表示中のページに今回の停止のシステムメッセージがない場合は、停止日時を使って画面上に案内を補う。機能追加前の停止や、案内が別ページにある会話でも、主催者・参加者・運営・通報詳細の履歴で停止状態を確認できる。同じページに該当メッセージがある場合は重複表示しない。この補完ではメッセージ保存・通知予約・既読更新を行わず、利用停止解除後は補完表示しない。保存済みの過去の停止履歴はそのまま残る。

導入直後は保留投稿を確認し、誤検知の理由を見ながら `ChatSpamDetector::REASONS` の条件・点数を調整する。既存メッセージは再判定せず配信済みとして保持する。
