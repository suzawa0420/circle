# サークルブック デザインルール

更新日：2026-10-02 / サイト共通適用 v2

## 方針と適用範囲

白と薄いグレーをベースに、緑を主要な操作と選択状態に使う。親しみやすさは公式のリスのイラストで表現し、本文と操作は読みやすく簡潔にする。

この文書は**サイト共通のデザイン標準**。アプリケーションレイアウトの公開・管理画面に共通スタイルを適用している。画面の役割に応じて配置は変えても、色・文字の役割・操作状態は揃える。既存テンプレートのクラスは `_site_design.scss` から共通値へ接続し、新規部品は `.cb-*` を使用する。メール本文と運営専用レイアウトは適用範囲外。

## 管理方法：SCSSとMarkdownを併用

| 管理するもの | 正本 | 理由 |
| --- | --- | --- |
| 色の値 | [`_brand_palette.scss`](../app/assets/stylesheets/_brand_palette.scss) | 既存スタイルとBootstrapも参照している。色を二重管理しない |
| 文字・余白・角丸・幅・動きの値 | [`_design_tokens.scss`](../app/assets/stylesheets/_design_tokens.scss) | デザインの共通値を一か所で変更する |
| 再利用するスタイル処理 | [`_design_mixins.scss`](../app/assets/stylesheets/_design_mixins.scss) | 既存クラスにも同じルールを適用できる |
| 新規ページ向けの共通クラス | [`_design_components.scss`](../app/assets/stylesheets/_design_components.scss) | ボタン・カード・入力欄を同じ部品で実装する |
| 既存ページへの適用 | [`_site_design.scss`](../app/assets/stylesheets/_site_design.scss) | `body.cb-site` 配下で、検索・詳細・編集・静的ページ・アカウント画面を共通値へ接続する |
| 目的・使い分け・文章・表示条件 | この文書 | 値だけでは伝わらない判断を残す |
| 複雑なHTMLや表示条件 | Railsの共有partial / helper | SCSSで認証・権限・導線を判断しない |

**数値はSCSS、意図はMarkdown**を原則とする。表の値を変えるときはコードと文書を同時に更新する。関数にすべてを詰め込まない。

- 変数：色、角丸、幅など単一の値。
- 関数：値を返す処理。`cb-space(4)` は16pxを返す。
- mixin：複数のCSS宣言と状態をまとめる処理。`cb-type(page-title)`、`cb-button(secondary)`など。
- 共通クラス：テンプレートからそのまま使う部品。`.cb-button`など。
- ページ固有のSCSS：レイアウト、画像比率、部品同士の配置。共通値は再定義しない。

現在のSassC環境で動く`@import`とmixinを使用する。Sassの実行環境を更新するまでは`@use`への置き換えを混在させない。`@extend`によるページをまたぐ継承も避ける。

## 色

| 用途 | SCSS | 値 |
| --- | --- | --- |
| 主操作・ブランド | `$cb-action` | `#16835d` |
| 主操作のhover・濃い緑のリンク | `$cb-action-hover` | `#0f6849` |
| ページ背景 | `$cb-canvas` | `#f5f6f7` |
| カード・入力欄 | `$cb-surface` | `#ffffff` |
| 選択・軽い強調の背景 | `$cb-mint-soft` | `#edf7f2` |
| 本文・見出し | `$cb-text` | `#202124` |
| 補足・メタ情報 | `$cb-muted` | `#656b73` |
| カードの境界 | `$cb-border` | `#e3e6e8` |
| 入力欄・副ボタンの境界 | `$cb-input-border` | `#b6bcc1` |
| エラー・削除 | `$cb-danger` | `#b83e46` |
| エラー背景 | `$cb-danger-soft` | `#fff1f2` |
| 注意文と注意背景 | `$cb-warning-text` / `$cb-warning-soft` | `#76551c` / `#fff5de` |
| 口コミの星 | `$cb-rating` | `#d97706` |

- 基本は緑1色。種目・ページごとに異なるアクセント色を増やさない。
- 赤はエラー・削除などに限定する。警告は緑の通常案内と区別する。
- 外部サービスの共有ボタンはサービス固有色を例外として使える。
- `$cb-sky`や`$cb-orange`などは既存画面用の互換変数。新規実装では意味が明確な変数を使う。
- 色だけで状態を伝えず「公開中」「選択中」「エラー」などの文字も表示する。

## 文字

OS標準の日本語ゴシック体を使用する。標準のフォント指定は`$cb-font-family`。装飾フォントや新しいWebフォントをページ単位で追加しない。

| 役割：`cb-type(...)` | スマホ / PC | 太さ | 行間 | 用途 |
| --- | --- | --- | --- | --- |
| `page-title` | 24 / 28px | 700 | 1.35 | ページのh1 |
| `section-title` | 20px | 700 | 1.4 | セクションのh2 |
| `card-title` | 16px | 700 | 1.4 | カード内の見出し |
| `body` | 16px | 400 | 1.8 | 説明文・長文・入力文字 |
| `compact` | 14px | 400 | 1.7 | 一覧カード内の短い情報 |
| `label` | 14px | 700 | 1.5 | 入力ラベル・ボタン |
| `helper` | 13px | 400 | 1.7 | 入力補足・説明 |
| `caption` | 12px | 400 | 1.6 | 更新日・補助的なメタ情報 |
| `display` | 32 / 36px | 700 | 1.3 | LPの主見出しだけ |

- 400と700を基本にする。大きさ・太さ・余白で階層を作る。
- 本文と重要な操作は小さくしない。通常の文字は12px未満にしない。
- 固定ナビの長いラベルなどは既存の10〜11pxを例外として扱い、短いラベルと押しやすい領域を優先する。
- 通常の字間は0。長文・ボタンに一律の1px字間を適用しない。
- 見出しを四角い枠で囲まない。h1は原則左寄せ、1ページに1つ。
- フォーム入力文字は16px以上。日付・件数は読みやすく、必要なら桁幅を揃える。

## 余白・角丸・幅

| スケール | `cb-space(...)` | 主な用途 |
| --- | --- | --- |
| 4 / 8px | `1` / `2` | アイコンと文字、ラベルと入力欄 |
| 12 / 16px | `3` / `4` | ボタン内側、カード内の情報間 |
| 20 / 24px | `5` / `6` | PCカード内側、フォーム項目間 |
| 32 / 40 / 48px | `8` / `10` / `12` | セクション間、導入部 |

- スマホの左右余白は16px。通常カード内側はスマホ16px、PC20px。
- 角丸は入力欄・ボタン8px、カード16px、ダイアログ20px。丸いアイコンや状態バッジは999px。
- 本文コンテナは最大760px、単独フォームは最大640px。検索一覧などの複数列レイアウトは別途指定できる。
- PCへの切り替えは768px。狭いスマホ320〜359pxでもURL・長い名前・ボタンが収まるようにする。
- 通常カードは白＋1pxの境界。影は補助的に使い、カードごとに強い影を増やさない。
- 情報の階層を枠の入れ子だけで表現しない。左側だけのアクセント枠も使わない。

## ボタンとリンク

| 種類 | クラス | 用途 |
| --- | --- | --- |
| 主操作 | `.cb-button` | 登録、送信、保存など、その領域の一番重要な操作 |
| 副操作 | `.cb-button.cb-button--secondary` | 編集、公開ページ、コピー、キャンセルなど |
| 軽い操作 | `.cb-button.cb-button--ghost` | 補助的な切り替え・詳細表示 |
| 破壊的な操作 | `.cb-button.cb-button--danger` | 削除など。主操作と離し、必要な確認を置く |
| 本文中のリンク | `.cb-text-link` | 文中の移動先。下線でリンクと分かるようにする |

- ボタンは原則48px以上の高さ。小サイズでも44px以上の操作領域を確保する。
- 同じ操作グループで主操作を乱立させない。全幅が必要なら`--block`を使う。
- 遷移には`a`、送信・ダイアログ・コピーなどには`button`。`button`のtypeを明示する。
- 「こちら」ではなく「無料新規登録」「公開ページ」「コピー」など結果が分かる文言にする。
- hoverは背景・境界を変える。ボタンを半透明にして文字まで薄くしない。
- focusは緑2pxの輪郭と3pxの間隔。キーボードでも押せるようにする。
- disabledは実際に操作不可にする。`aria-disabled`だけではクリックを止められないため、JS側でも処理を止める。
- 送信中は「送信中…」などを表示し、二重送信を防ぐ。`aria-busy`も必要に応じて付ける。
- コピー成功は「コピーしました」。失敗時は再試行や手動コピーの方法を示す。

## フォーム・案内・ダイアログ

- ラベルは入力欄の上。placeholderだけで入力内容を説明しない。
- ラベル→入力欄は8px、補足は下に8px、項目同士は24px。
- エラーは対象入力欄の近くに文章で表示する。`aria-invalid`、`aria-describedby`を付ける。
- 注意文は薄い背景と通常の境界でまとめる。重要でない説明をすべて警告色にしない。
- 確認・認証ウィジェットと次の項目の間は24px以上を確保する。
- ダイアログには名前、閉じるボタン、Escで閉じる動作、開く前の場所へ戻るフォーカスを用意する。
- 一覧選択は画像＋名前で統一し、現在の項目には「選択中」を表示する。
- データが空のときは状況と次の操作を示す。大きな余白と文章だけで行き止まりにしない。
- 動きは180msを標準とし、動きを減らす設定では無効にする。

## サークルブック固有のルール

- 主催者と参加者は画像・見出し・説明で区別する。新規登録とログインは別ボタンにする。
- サイトの無料利用を説明する。サークル活動そのものの参加費が無料であると誤解させない。
- 「最短30秒」などの時間表現は、計測や条件を確認してから使う。メール到着・認証にかかる時間は保証しない。
- マスコットは既存の公式リス画像を使用。飾りよりも役割説明や空の状態の案内に使う。絵文字でアイコンを代用しない。
- 主催者の管理画面では現在のサークル画像・名前を1回だけ表示して切り替えに使う。左下の固定ナビの現在アイコンは操作上の別導線として残せる。
- 管理カードの右側に編集・公開ページ、その下に公開URL全文とコピーを置く。URLは折り返し、省略や非表示にしない。
- レベルは自分のサークルの管理画面に表示する。例外として、主催者マイページの「ライバルサークル」欄だけ同じ都道府県・種目の公開サークルのレベルを表示する。公開一覧や通常の詳細・比較欄には表示しない。表示条件はRuby側で守る。
- 未ログイン：サークル検索／無料登録・ログイン／メニュー。
- 参加者：サークル検索／メッセージ／お気に入り／メニュー。
- 主催者：メッセージ／スケジュール／ブログ／メニュー。管理画面では左端にサークル切り替えを追加し、会話画面では省く。
- 未読件数と選択状態は文字やバッジでも示す。ナビはsafe-areaと本文の余白を確保する。

## 実装例

`application.scss`から共通クラスを読み込み済み。新規部品は共通クラスで使用する。既存画面は `body.cb-site` の共通適用スタイルも読み込む。

```haml
.cb-page.cb-page--form
  %h1.cb-page-title サークルを編集
  .cb-card
    %h2.cb-card-title 基本情報
    .cb-field
      %label.cb-field__label{ for: "circle-name" } サークル名
      %input#circle-name.cb-field__input{ type: "text", "aria-describedby" => "circle-name-help" }
      %p#circle-name-help.cb-field__help 参加者に表示される名前です。
    %button.cb-button{ type: "submit" } 保存する
    = link_to "公開ページ", circle_path(@user), class: "cb-button cb-button--secondary"
```

実際のフォームでは既存のRails form builderと認証・検証処理を使う。上記は表示構造の例。

既存クラスを維持して段階移行する場合：

```scss
@import "design_mixins";

.circle-edit__title { @include cb-type(page-title); margin-bottom: cb-space(6); }
.circle-edit__panel { @include cb-card; }
.circle-edit__save { @include cb-button(primary); }
```

## 今後の進め方

1. 変更するページの役割と一番重要な操作を決める。
2. 色・文字サイズ・余白を共通値に置き換える。ボタン・入力・カードは共通クラスかmixinを使う。
3. 繰り返すHTMLや条件分岐を共有partialへまとめる。画像・名前・操作の重複を減らす。
4. 320px・393px・PCで、長い名前、URL、空の状態、エラー、未ログイン、所有者以外を確認する。
5. キーボード、focus、disabled、送信中、固定ナビによる隠れを確認する。
6. 適用したページ固有の古い宣言を削除する。必要な例外は理由と適用範囲をこの文書に追記する。

優先順は、登録・ログイン→主催者／参加者マイページ→管理フォーム→サークル詳細・一覧→ブログ・質問・口コミ→その他のページ。

古い`doc/mobile-navigation-design-20260927.md`は過去の検討案として扱い、新規実装の基準はこの文書と現行の表示条件に合わせる。今回の適用範囲と検証記録は [デザイン統一の確認記録](design-rollout-20261002.md) を参照する。


## 既存画面への適用と例外

- `_site_design.scss` は既存の機能・フォーム名を保つための移行用スタイル。ここでも値の正本はtokens/mixins。追加の色やページ固有のスケールを作らない。
- `body.cb-site` はアプリケーションレイアウトだけに付与する。運営専用レイアウトやメールに共通フォームの指定を波及させない。
- 検索の日付一覧とタグは横スクロールを許可する。本文・フォーム・ページ全体の横スクロールは許可しない。
- サークル一覧のカバー画像、詳細の画像拡大、Trixツールバー、会話の入力欄、固定ナビには専用の配置を残す。色・文字・操作領域を共通ルールへ揃える。
- スマホは既存の役割別下部ナビ、PCはロゴと検索・アカウント導線を持つ共通ヘッダー。PCヘッダーは72px分の本文余白を確保する。
- レガシーの詳細カード内テーブルは、項目名28%・値72%を基本とし、長い値を折り返す。
- SassCはアセット圧縮時にもCSSを処理する。単体のSCSS変換に加え、Railsで `application.css` 全体の生成を確認する。
- 広告・外部地図・認証ウィジェットの中身は外部提供元の表示に従う。サイト側の余白とコンテナを整える。

## サークル・活動日の説明本文と募集状態

- 公開詳細の説明本文は `.cb-reading-body` を使用し、カード内に追加の枠を設けない。本文領域の横幅を使い、16px・行間1.95・段落間1.25emを基本にする。リンクと強調文字も本文の文字サイズに揃える。
- 募集中は `$cb-action`、募集終了・満員は `$cb-danger` と白文字。中止は `$cb-warning-soft` と `$cb-warning-text`。ヘッダーのリボンと活動日の募集ラベルは同じ意味の色を使い、状態の文字を必ず表示する。

- ブログ詳細は本文の左右余白を20pxにし、下部のサークル情報と左端を揃える。16px・行間1.95の読み物用スタイルを使う。共有ボタンは背景色と区別できる白文字・白アイコンを保つ。
- 通常のテキストリンクとサークルカードは、ホバー・フォーカス・押下で文字色を変更しない。キーボード操作のフォーカス枠は残す。

## 利用者別の配色

- 主催者と共通検索は既存の緑（#16835d）。参加者は青（#2469a8）、濃い青（#1b5183）、薄い青（#edf4fb）を使う。
- 参加者の登録・ログイン、マイページ、プロフィール、保存、お問い合わせ、メッセージ送信・口コミ入力の操作を青にする。混在画面では参加者向け要素だけ `cb-participant` で指定する。
- 共通ボタンのmixinは役割のCSS変数を継承する。参加者画面は `participant-shell`、参加者の会話は `cb-participant` を使う。
- 会話のアイコンと吹き出しは発言者の役割で色を分ける。主催者の自動案内・サークルのアイコンは緑を保つ。
- 募集状態、削除、警告、星評価は既存の意味別の色を保つ。色だけで区別せず、役割名・アイコン・ラベルも残す。
- サークルのプロフィール画像がない場合は、サークル名の頭文字を緑系の背景で表示する。

## 運営・システム通知の配色

- 運営の操作・システムのお知らせは紫（#7552a3）、濃い紫（#583b80）、薄い紫（#f3eef9）、境界線（#dbcee9）を使う。
- 受付状況、口コミ投稿期限、メール確認案内、処理完了の通知は `cb-system-notice`、運営由来の操作パネルは `cb-system-panel` を使う。必要に応じて「システム通知」などのラベルを添える。
- 注意・警告は既存のオレンジ系 `cb-warning-notice`、削除やエラー項目は既存の赤を使う。
- 自動送信かどうかではなく、内容の発信元で色を決める。主催者が設定した初回案内や登録した活動日の案内は緑を維持する。
- 運営管理画面の共通操作は紫。会話履歴の主催者は緑、参加者は青とし、運営が閲覧しても発信元の配色を変えない。
- 既存の保存データで `sender_role=system` は主催者の初回案内を表している。これを運営の発言として表示し直さない。今後、運営メッセージ機能を追加する場合は発信元を明示的に区別する。

- 会話履歴の発言者ラベルは共通の `message-role` を使う。主催者・主催者由来の自動案内は `message-role--owner`（緑）、参加者は `message-role--member`（青）、運営由来の通知は `message-role--system`（紫）。通常チャット、運営の会話閲覧、通報画面で統一する。

## UIアイコン

- Font Awesomeを廃止し、Lucide（lucide-static 1.52.0）へ統一。SVG形状はサイトに同梱し、JavaScriptや外部CDNに依存せず表示する。ライセンスは `vendor/licenses/lucide-LICENSE` に保存する。
- テンプレートでは `lucide_icon("calendar-days")` など共通ヘルパーを使う。SVG名は定義済みのものだけを許可し、装飾アイコンは支援技術から隠す。操作の名前はボタン本文・aria-labelで伝える。
- 基本線幅は2px。本文・ボタンは文字サイズに合わせ、固定ナビ24px、タブ・管理アクション20pxを基本にする。色はcurrentColorで既存の主催者・参加者・運営の配色を継承する。
- 星評価はLucideの星を塗りつぶし、保存済みはブックマークの塗りつぶしで状態を示す。色だけで状態を伝えない。
- ブランド専用マークは共有・カメラなど操作の意味に対応するLucideアイコンに置き換える。Trixのツールバー、画像拡大ビュー、日付選択の矢印もLucideのSVGマスクを使用する。
