# 公式施設情報の収集と登録

## 範囲と判定

初期収集元は公益財団法人世田谷区スポーツ振興財団の公式施設一覧
https://www.se-sports.or.jp/facility/ 。世田谷区内の体育館・コートから開始する。
検索エンジンや第三者サイトの転載は登録根拠に使わない。

一覧から施設ページを発見し、基本情報の住所・連絡先と、施設紹介先の基本情報に明示された対応種目を抽出する。
種目は面数・台数の明示を条件とし、ナビゲーションや利用料金欄にある別施設の案内を根拠にしない。
温水プール・トレーニングルーム名のページは、併設コートの案内があっても対象外とする。
屋内外が混在する複合施設、休館等のお知らせがある施設、情報不足、DBの地域・種目マスタと一致しない候補は確認待ちにする。
アクセス・駐車場・利用時間・休館日・施設規模・利用料金を施設専用の公式案内から取得し、すべて確認できた候補だけ自動登録する。
料金は個人／団体利用、曜日、時間枠、半面／全面などの見出しと表の結合セルを保持し、公式料金URLと確認日を添える。
情報不足は空欄のまま公開せず確認待ちにする。写真は自動転載しない。

施設名・住所の全半角、空白、番地記号、電話番号の区切り、URLのwww・末尾スラッシュなどを正規化して照合する。
名称の部分一致や同じ住所・電話番号も重複候補として保留する。既存施設は自動更新・削除しない。管理者が補完した登録済み施設の情報も上書きしない。
この照合で発見できない旧称・移転は残るため、開始後は登録結果を管理画面で確認する。

## 実行

マイグレーション後、プレビュー（候補・判定履歴のみ保存、施設は追加しない）:

```sh
bundle exec rake places:discover
```

条件を満たした候補を最大5件登録:

```sh
APPLY=1 LIMIT=5 bundle exec rake places:discover
```

LIMITは1〜20。重複・確認待ち・過去に登録済みの候補は登録上限を消費しない。
同じ情報源URLの再収集は同一候補を更新し、登録済み・管理者が見送った候補は再登録しない。
収集時はすべてのページ取得に成功してから候補処理する。収集失敗は実行履歴に失敗として残し、例外を返す。
途中の登録処理が失敗した場合、それ以前の登録結果は保持し、再実行時に再登録しない。

情報源は実装内の固定ホストとパスのみ許可。HTTPS必須、リダイレクト禁止、タイムアウト・2MiB上限・1秒間隔を設定。
robots.txtのDisallowを保守的に適用し、取得できない場合は収集を中止する。
一覧の先頭24施設、施設あたり8詳細ページまで。上限を超えるサイトへの拡張時はページングと巡回順を追加する。
新しい自治体は専用Sourceを追加し、公式ホスト・HTML構造・利用条件・種目根拠を確認してからRunnerに組み込む。
未知のサイトを自動で信頼対象に加えることはしない。

## 管理画面

`/super_admin/place_import_candidates`（施設管理画面から移動可能）。既存のwebmaster認証必須。
候補の情報源、種目の根拠、確認日時、休館のお知らせ、重複先のID、最近10回の実行結果を表示。
「条件を再確認して登録」でも同じ登録条件・重複検査を適用する。7日以上前の情報は再収集が必要。
曖昧な候補は公式情報と既存施設を確認して既存の手動登録画面を利用し、候補を見送る。

## 日次実行（本番への反映は別途）

この変更だけでは本番での収集・登録・定期実行は開始しない。
本番デプロイとマイグレーション、最初のプレビュー結果確認後、許可された範囲でserver4だけに
`circle-place-import.service` / `.timer` を設置し有効化する。server5と二重起動しない。
毎日05:20 JSTから最大15分の分散遅延で実行し、1回最大5件を登録する。
同一サーバーでの重複起動はファイルロック、都道府県ごとの登録処理はDB行ロックで直列化する。

```sh
sudo install -m 644 ops/al2023/circle-place-import.service /etc/systemd/system/
sudo install -m 644 ops/al2023/circle-place-import.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now circle-place-import.timer
```

状態確認はタイマーの稼働状態と管理画面の実行履歴を使用する。外部への通知送信はしない。
停止は `sudo systemctl disable --now circle-place-import.timer` 。実行中の処理も止める場合はserviceを停止する。
プロセス強制終了時は履歴が実行中のまま残り得るため、タイマー状態と突き合わせる。
ロールバックはまずタイマー停止、その後アプリの旧版への復帰。追加テーブルは保持する。
自動登録済みの施設は旧版でも通常の施設として表示できる。施設の一括削除は行わない。

## 全国の対象を順番に処理・再開する

全国用の情報源は、許可済みの `shisetsu.mizuno.jp` の施設個別ページと
`sports-service.mizuno.jp/search/` の公式施設一覧。
2026-10-25時点では全国一覧が臨時メンテナンス中で503応答のため、一覧の全件取得は完了扱いにしない。
`config/place_import_mizuno_seeds.json` に公式案内・イベントページで確認した既知37施設のURLと発見元を保存している。
一覧が利用できない間も既知の対象を処理でき、復旧後の発見分は同じキューへ追加する。
許可していないドメインへのリダイレクト、画像やPDFにしかない料金、種類が曖昧な複合施設は自動登録しない。
一覧が未取得の場合、全体の `complete` は未処理がゼロでもfalseのままにする。

```sh
# 保存済み対象の追加＋最大10施設の収集・判定（施設は公開登録しない）
bundle exec rake places:nationwide
# 登録可能な対象を最大10施設ずつ処理。次回は残りから再開
APPLY=1 BATCH_SIZE=10 bundle exec rake places:nationwide
# 一覧の再取得を省略して保存済みキューを続行
APPLY=1 DISCOVER=0 BATCH_SIZE=10 bundle exec rake places:nationwide
# HTTP要求なしで件数・残り・全国一覧の取得状態を確認
bundle exec rake places:nationwide_status
# 運営が明示した確認待ち施設だけ再収集。登録済みは対象外
IDS=101,102 bundle exec rake places:nationwide_retry
```

BATCH_SIZEは1〜20。施設単位の状態は `queued`（未処理）、`collected`（収集済み・判定待ち）、
`ready`（プレビューで登録可能）、`registered`（登録済み）、`duplicate`（重複候補）、
`pending`（情報不足・取得失敗）、`dismissed`（見送り）。
重複候補・情報不足は確認待ちとして保持し、自動で再試行・上書きしない。
明示指定の再収集以外は、完了した施設を再取得・再登録しない。
処理を中断しても未処理・判定待ち・登録可能の対象をID順に再開する。
施設の公開登録と最終状態の保存は同一トランザクションで行い、片方だけ完了しないようにする。
予期しない実装例外では実行を失敗にして止め、対象の判定待ち状態を残す。

30分間隔の継続処理には `circle-place-nationwide.service` / `.timer` をserver4だけで使用する。
新しい本番反映とタイマー有効化は事前承認を得てから行う。既存の世田谷用タイマーとは共通ファイルロックで排他する。
1回最大10施設、HTTPは1秒間隔で順番に取得し、既存サーバーと公開情報だけを使う。
新しい有料API・外部契約・サーバープラン変更は使わない。

承認後の設置・有効化:

```sh
sudo install -m 644 ops/al2023/circle-place-nationwide.service /etc/systemd/system/
sudo install -m 644 ops/al2023/circle-place-nationwide.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now circle-place-nationwide.timer
```

全国一覧の取得が成功し、未処理・判定待ち・登録可能がすべてゼロになったら処理対象全体の完了。
運営が件数を確認して `sudo systemctl disable --now circle-place-nationwide.timer` で継続処理を終了し、
登録件数・重複候補・情報不足・見送り・未処理件数を報告する。
一覧がメンテナンス中の場合は既知対象の処理完了と全体完了を区別して報告する。
停止・ロールバック時も、候補と既存施設は保持する。DBの直接修正や登録済み施設の一括削除は行わない。
